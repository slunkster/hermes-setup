# Estonian grant applications (taotlus)

Class of task: prepare or review an Estonian community/youth funding application for the e-toetuse keskkond (e.g. KOP — Kohaliku omaalgatuse programm, similar RTK or ministry rounds). Drafting deliverable: a draft the user pastes field-by-field into the web form, plus a budget built to the funding ceiling and a submission checklist. Review deliverable: a prioritised correction list for an existing export (step 9). Round-specific rules live in `references/kop.md`.

## Workflow

1. **Find the working draft.** The user keeps their e-toetuse export in `~/Downloads` as `taotlus_<projektinr>_<ddmmyyyy>_<hhmmss>.pdf`; several exports may exist — take the newest (timestamps are in the filename). `read_file` extracts PDF text natively: the export contains every form page, the helper texts, the taotlusvoor line and whatever the user already entered — it is the source of truth for field names and the project number. First pass only, though: its text flow merges multi-column labels/values and scrambles table cells, so for value→field attribution, character counts, or suspected typos re-extract with coordinate blocks (step 9).
2. **Fetch the round rules before writing.** Administering body pages (RTK meede page + the county MARO site), the määrus on riigiteataja.ee (toetussumma ja %, abikõlblikud ja mitteabikõlblikud kulud, taotleja nõuded) and the hindamismetoodika (criteria + weights — aim every text field at these). Pull the current official näidisvorm too and diff your draft against it field-by-field; that is how form quirks surface. RTK cloud share links download with `curl -sL "<share-url>/download" -o f`; the file often lands named `.zip` but is actually `.docx` — check `file f` and rename before reading.
3. **Research the beneficiary beyond the minimum.** Village/parish statistics, the venue and partner organisation, recent local news (parish site, county paper, Facebook), applicant-org registry data (inforegister / e-krediidiinfo), and the county's list of previously funded projects — find a comparable funded precedent (same cost type) to cite the pattern. For the applicant's or partners' past EU-programme projects (ESC / Erasmus+ histories, double-funding checks), use the `esc-erasmus-project-research` skill (kaart.noored.ee + EU registries).
4. **Write the draft as a numbered .md** saved next to the source in `~/Downloads`, sections mapping 1:1 to the form pages in order (name, dates, taotleja blurb, every Sisu text field, näitajad + selgitused, tegevused + tõendusmaterjal, eelarve, rahastajad, checklist, sources). Every paste-ready text sits under a `KOPEERI:` line of its own. Count character-capped fields (e.g. „lühikokkuvõte avalikkusele” ≤ 500 tähemärki) programmatically before delivering.
5. **Budget to the ceiling.** Set abikõlblik kulu = toetus-lagi / 0,9 rounded DOWN to cents, so the form's computed 90 % equals the cap exactly (4 000 € cap → 4 444,44 €); omafinantseering = the remainder (= 10 %, rahaline). Absorb odd cents into one accessories/bundle line; anchor other prices on real market listings; walk the list against the mitteabikõlblikud costs before finalising.
6. **Verify programmatically, then package.** Check: budget rows sum to the claimed total — re-sum after every row edit, re-anchoring rows to real market SKUs shifts the total silently, restore the exact ceiling via a „hinnanguline“ bundle line; 90 % maths lands on the exactly capped toetus; capped text lengths counted; zero leftover user placeholders ("Lorem ipsum", "test"). Deliver `.md` + a `.docx` copy in `~/Downloads` and confirm the docx parses by reading it back (dependency-free fallback if needed: zip a minimal packet by hand — `[Content_Types].xml`, `_rels/.rels`, `word/document.xml` with XML-escaped `<w:p>` paragraphs, bold/size via `<w:rPr>`).
7. **Also deliver the budget as its own working file.** Besides the taotlus draft the user wants a standalone eelarve + hinnavõrdlus document for their own use („eraldi pdf oleks mulle endale“): the full itemised budget summing to the exact ceiling; per line two comparable real offers (product, store, price, source) with a pick/reason; estimate-only lines marked „hinnanguline“; method notes (VAT, eligibility window, keep-the-total rule); and a ready-to-send hinnapäringu kiri (mall) with furniture/technology item lists for ≥ 2 suppliers each. Point to it from the checklist as a working file, not a mandatory attachment. Build it from `templates/eelarve-hinnavordlus.html`, print to PDF via the browser harness (`new_tab("file:///…html")` → `cdp('Page.printToPDF', printBackground=True, preferCSSPageSize=True)` → decode base64 `data`, write the .pdf beside the .html so rows can be tweaked and re-printed), and verify via `read_file` text extraction or by opening the `file://…pdf` and screenshotting. Don't shell out to a Chromium-family binary for print-to-pdf — it can hang under the terminal sandbox. Budget-number changes go into the taotlus text and this file together.

8. **Close in Estonian, short.** What the round is (max toetus, %, deadline), the file paths, and the must-do list before submission (price quotes, confirmations, agreements, open placeholders). Offer to finalise prices or rewrite sections.
9. **Review mode — checking an existing export before submission.** A QA pass, not drafting; expect repeat rounds as the user fixes fields and re-exports. Take the newest `taotlus_*.pdf` in `~/Downloads`; when an earlier export exists, diff the two block-dumps (old → new) to see exactly what changed.
   - Precision pass first: plain text extraction merges multi-column labels/values, scrambles table cells and invents phantom fragments — before reporting ANY suspected error (fragmented quotes, misplaced text, value→field mapping), re-extract with coordinate blocks (`scripts/export_review.py`; PyMuPDF, blocks sorted by (page, y, x)) and attribute every value to its field by position. Quote-tail fragments and mid-sentence label merges are usually extraction artifacts.
   - Contradiction sweep: projekt algus/lõpp = the vooru window exactly (NB), every activity date inside it; one fact = one value across fields (move month in kirjeldus vs tegevus, age ranges, opening hours vs the KOV's published hours, partner name vs äriregister); the fixed-indicator täpsustus texts sit under the CORRECT indicator (verify by y-coordinates — they get swapped); mid-sentence cuts (same cut point across exports ⇒ copy/limit issue, not editorial); leftover placeholders („Lorem ipsum”, „test”, „või ...”, a literal `---` in a free-text field, empty required fields).
   - Known non-errors, do not report: „Makse saaja pangas” shows the applicant's name (auto-filled by design); quote fragments from extraction. What IS reportable: the riigihange dropdown left at „Ei” instead of „Ei kohaldu”.
   - Ground rules in the current näidisvorm + juhend (.docx from the county page) and the määrus (§ 11: deadline 16.30, >1 000 € purchases need the two quote results in the taotlus text, investment docs: kasutusõigus / avaliku kasutamise leping + KOV kinnitus). Fetch the määrus via the Riigi Teataja public JSON API with plain curl (recipe: the Riigi Teataja reference inside the `statutory-law-research` skill) — the regular act page URL returns only a JS shell.
10. **Eligibility mode — "can X apply / is there no other way?"** A cited yes/no, not a draft. Order:
   - Read the CURRENT määrus (RT API version list → `kehtivRedaktsioon`); when the user attaches a PDF of the act, check its header („Redaktsiooni jõustumise kp”, „Hetkel kehtiv”) against that list instead of trusting it.
   - Then the administering agency's KKK page and any info-session slides (infopäeva esitlus) — they routinely answer the exact edge case (e.g. a degree without the required kutse) and show what the e-form actually accepts (a field auto-filled from Kutseregister = no manual alternative).
   - Check today's date against the taotlusvoor window; say plainly when the round closes today/has closed and which round is the realistic one.
   - List only the legitimate alternative routes the text allows (another collective type/qualification route, another eligible person, getting the qualification for the next round, other funders), each tagged verified or not verified.
   - Slide-deck PDFs are often image-only: `pdftotext -layout` gets the text slides; render the rest per page (`pdftoppm -r 110 -png -f N -l N`) and read them with vision.
   - Answer shape (this user): verdict in the first line, § + lg citations, alternatives, timing, contact person, plain source URLs; follow-ups ("vaata siit ka") get a short delta answer — what the new document adds or confirms, not a rerun.
   - Feedback shape (this user): Estonian; „KOHUSTUSLIKUD PARANDUSED” numbered with paste-ready replacement strings where short → „VASTURÄÄKIVUSED” → „MUU KONTROLL” → compact „KEELEPARANDUSED” (before → after) → „MIS ON KORRAS”. Re-review rounds open with the „parandatud” items, then only what is still open — and proofread the blocks the user just edited: quick fixes regularly introduce fresh typos inside the rewritten sentence.

## Conventions (this user)

- Everything in Estonian; field labels exactly as the form shows them.
- Never invent local facts (visitor counts, member counts, agreement dates). Insert explicit placeholders like `[ARV]` / `[KUUPÄEV]` and list every open placeholder in the closing checklist.
- Closing checklist must cover: two hinnapäringut for larger purchases with results written into the budget text; KOV written confirmation; public-use/cooperation agreement where the measure requires it; representation-right check in the business register; double-funding check; deadline and the MARO adviser contact.
- End with a sources block (links) so facts can be re-verified.

## Pitfalls

- **Project period:** fill start/end exactly as the form's `NB!` instructs (KOP: the eligibility window itself — „muud kuupäeva mitte märkida”); put any narrower dates on the activity row instead. Formal date mismatches are cheap rejection fodder.
- **KOP riigihange dropdown = „Ei kohaldu”**, not „Ei” — the official näidisvorm says so explicitly.
- **Investment-measure applicant must own the object** or hold a usage right + avaliku kasutamise leping ≥ 3 years beyond the eligibility end; KOV kirjalik kinnitus among the taotlus documents (§ 11 (4) 14 — worded literally for construction investments; for equipment/furniture purchases confirm with the MARO whether it is required). Movables bought by an MTÜ for a municipal venue: the MTÜ keeps ownership, the agreement documents public use — put both on the checklist, don't leave them implicit.
- **Costs over 1 000 €:** the taotlus text must carry two comparable hinnapäringu RESULTS + choice justification (the quotes themselves are not attached); the eelarve rea täpsustus field is where they go.
- **Double funding:** check other projects (same venue/org/municipality) before answering the "previous related funding" yes/no.
- **Late impact angles go through EVERY field.** When the user widens the project's target mid-draft (intergenerational cooperation, formal/non-formal learning integration, …), thread it through all Sisu texts, the näitajate täpsustused (and any count the item list changes), tegevused + tõendusmaterjal, and kasusaajad; then re-count capped fields, re-verify, and sync the separate budget file. Such angles are criterion boosts — write them as results/impact (criteria 1–2), not as activities.
- **The draft PDF shows the user's half-filled values** (placeholder name, wrong dates, test numbers in the indicators) — diff against the näidisvorm and call out each fix explicitly in the checklist.
